# uaef-agent-eval-poc

Replay of 10 saved agent sessions through [awslabs/uaef](https://github.com/awslabs/uaef) (Universal Agent Evaluation Framework), compared with the scores AgentCore Evaluations gave the same sessions.

The agent under test is a small cost-explainer: a Strands agent on Amazon Bedrock AgentCore Runtime with one tool (`get_cost_breakdown`, backed by Cost Explorer). The sessions and their AgentCore scores come from a run on 2026-07-30. In that run, `Builtin.Correctness` scored a false answer 1.0 (question 5: "no service shows a negative cost"). This repo asks what UAEF says about the same 10 answers when it is given a ground truth that was checked by hand.

## What is in here

| Path | What |
|---|---|
| `data/ground-truth.json` | 10 questions and the expected answers, verified by hand against Cost Explorer |
| `data/transcripts/` | The agent's 10 answers as the AgentCore CLI printed them, plus session ids |
| `data/agentcore-evals/` | Saved AgentCore Evaluations output for those sessions (Correctness, Faithfulness, ToolSelectionAccuracy, InstructionFollowing) |
| `replay.py` | Builds UAEF traces from the transcripts and runs the metrics |
| `summarize.py` | Builds `results/summary.md` from the saved runs |
| `results/` | The runs behind the numbers: `summary.md`, one JSON per judge |

## Run it

Requires [uv](https://docs.astral.sh/uv/) and, for the judge metrics, an AWS account with Amazon Bedrock access to the judge models.

```bash
uv sync

# No AWS calls: only the deterministic metric (tool_selection_accuracy)
uv run python replay.py --offline

# Full run: Haiku 4.5 x3, then Opus 4.6 x1 as control
aws sso login --profile <profile>
export AWS_PROFILE=<profile> UAEF_POC_ACCOUNT_ID=<12-digit account id>
./run-all.sh

uv run python summarize.py     # rebuild results/summary.md from results/*.json
```

`replay.py` aborts unless the caller's account equals `UAEF_POC_ACCOUNT_ID`, so a wrong profile cannot spend money in the wrong account. Judge calls are real Bedrock invocations and are billed to that account.

## Pinned

UAEF is installed from commit `dc55d8ca54331176bb16744b9cc680f806075700` (v0.2.0, classifier `Development Status :: 3 - Alpha`) and is not modified. `uv.lock` pins the rest.

## Judge models

UAEF 0.2.0 sends `temperature` in every `InvokeModel` call. In the account used for these runs, Sonnet 5.5, Opus 5.5, Haiku 5.5, Sonnet 5 and Opus 4.8 rejected it (`temperature is deprecated for this model`), and UAEF's default judge (Sonnet 4.6) failed with an AWS Marketplace access error. Haiku 4.5 and Opus 4.6 accepted the call, so those are the judges. Your account may differ: set `UAEF_LLM_MODEL_ID` to another Claude model ID if you want to try one.

`UAEF_ENABLE_CACHING=false` is exported as a precaution. In the pinned commit the flag is read in `config.py` and not referenced anywhere else, so it appears to have no effect on judge calls.

## How the metrics were fed

- `accuracy`, `completeness`, `answer_relevance` use the expected answer from `ground-truth.json` as the reference.
- `hallucination_score` needs `context` and returns no score without it. It runs twice: once with the tool output as context (what the trace says) and once with the facts verified by hand in Cost Explorer (what is true). Results for the second run are stored under `hallucination_score@world`.

## Limitations

- Traces are reconstructed from CLI transcripts. The tool result comes from text quoted in AgentCore's own evaluator output, and the tool-call arguments were never captured (left empty). `tool_selection_accuracy` is therefore 1.0 by construction and carries no signal.
- UAEF only receives `expected_output`. For question 7, the original assertion also accepted "the daily breakdown is not available in the tool output", which UAEF cannot express, so its 0.00 on q7 is a false positive from how the ground truth was mapped, not an agent error. It was not re-tuned after seeing the result.
- AgentCore and UAEF used different judges, prompts and reference data. The comparison is between two evaluation setups, not between two identical judges.
- The ground truth is a snapshot: the agent's tool queries a rolling 7-day window, so re-invoking the agent today would be judged against stale answers.

## Not exercised

- `persist=True` (DynamoDB and S3 experiment tracking and regression detection) and the `uaef-service` deployment.
- `AgentCoreAdapter.invoke()`, the live call to a runtime ARN. Sessions were replayed from saved transcripts.
- Judge cost in dollars.
